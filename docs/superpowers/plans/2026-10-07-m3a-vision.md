# M3a Vision Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Sort pieces using only what an overhead RGB-D camera sees, with open-vocabulary naming, and measure the cost against ground truth.

**Architecture:** A new `lab_perception` package (pure-Python core: camera model, depth segmentation, embedding-based naming; thin ROS node) publishes `vision_msgs/Detection3DArray`. `lab_simulation.Scene` gains a pose source; tasks plan from observations and are scored on ground truth.

**Tech Stack:** ROS 2 Jazzy, Gazebo Harmonic rgbd_camera, NumPy/SciPy, PyTorch (CPU) + transformers 5.x (SigLIP 2), pytest.

**Spec:** `docs/superpowers/specs/2026-10-07-m3a-vision-design.md`

## Spike results (recorded 7 October 2026)

- The rgbd_camera renders in the lab container once the world lists the Sensors system (`render_engine` ogre2); listing any world system means Physics, UserCommands and SceneBroadcaster must be listed too.
- Camera pose (0.55, −0.30, 1.30), yaw 2.481, pitch 0.767 (looks at (0.10, 0.05, 0.75)); hfov 0.9; 640×480. Topics `/lab/camera/{image,depth_image,camera_info}`; depth is 32FC1 metres along the optical axis.
- Uncapped real-time factor with the camera at 10 Hz: 2.2–5.4×.
- Depth blobs (5–70 mm above the table, 0.10–0.30 m from the pan axis, bin footprints masked, ≥ 80 px) + SigLIP 2 (`google/siglip2-base-patch16-224`): 90/90 named, 0 missed, 0 false over 30 random-light scenes; position error 6.0 mm mean (whole-blob centroid); 303 ms per crop on CPU. In transformers 5.x `get_image_features`/`get_text_features` return an object; use `.pooler_output`.
- EmbeddingGemma 2 needs a Hugging Face token; it is an optional backend added later.
- CI rendering untested; Task 4 checks it.

## Review Focus

1. A piece the camera cannot see (occluded, out of frame) must fail the trial as `not_found`, never pick a stale or ground-truth pose.
2. A detection frame older than the scene settle time must never be used (stale frames at uncapped speed).
3. Two blobs with the same label: the higher score is used, the other logged, never both picked.
4. In vision mode nothing the planner uses may come from ground truth, including the grip offset used to aim placement.
5. CI without a display must still run the ground-truth smoke test even if the camera cannot render there.

### Task 3: Naming

### Task 5: Vision mode in the tasks and benchmark

**Files:** modify `lab_simulation/{scene.py,tasks.py,benchmark.py,metrics.py,layout.py}`, launch files; tests `test_tasks.py`, `test_scene.py`, `test_metrics.py`, `test_benchmark.py`, `test_layout.py`.

**Produces:**
- `Scene.observe(timeout_s) -> Observation(poses: dict[label, PiecePose], detections: list, stale: bool)`; vision mode waits for a detection message stamped after the call (arm at home, pieces settled); ground-truth mode returns ground truth.
- Tasks plan from `observe()`: pick_place observes once at trial start; sort observes before each pick. Missing piece → `not_found`. In vision mode the placement aim uses the nominal grip offset `NOMINAL_GRIP = (0.009, 0.0, 0.0)` instead of the measured one.
- Per observation, `details['perception']` records each piece's matched label, error and missed/false counts (matching within 3 cm of truth).
- `layout.sample_yaws(rng)`, `layout.sample_light(rng) -> (direction, brightness)`; `Scene.reset(positions, yaws)`, `Scene.set_light(direction, brightness)` (`/world/table_world/light_config`, bridged service).
- `--perception {ground_truth,vision}` (default ground_truth); run info `perception`; comparability warning on mismatch; summary `perception` block (naming accuracy, position error mean/median/p95 mm, missed, false, latency ms).
- Cycle time excludes time spent waiting for detections; perception latency reported separately (wall ms).
